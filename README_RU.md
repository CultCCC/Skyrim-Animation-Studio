# SDS Anim Studio — этапы 0–7

[English version](README_EN.md)

Запуск: `dist\sds-anim-studio.exe`. Ничего ставить не нужно, нужны только системные DLL. Настройки сохраняются рядом с exe: `sds_anim_studio.json` и `sds_anim_studio_layout.json` (раскладка окон).

**Язык интерфейса:** переключатель **RU | EN** справа в строке меню, выбор запоминается. Для снимков есть ключ `--lang en`.

## Что умеет сейчас

- **Сборка MO2.** Порядок модов берётся из `modlist.txt` профиля, затем `overwrite`. BSA подключаются по `Skyrim.ini` профиля и по активным плагинам из `plugins.txt`. Loose-файлы всегда важнее BSA. Индексация вашей сборки занимает около 1 с: 694 мода, 149 BSA, около 396 тыс. файлов, 17 896 анимаций. Вместо MO2 можно указать обычную папку Data.
- **Библиотека.**
  - Режим «Папки» — дерево `meshes\**\animations\**.hkx`.
  - Режим «OAR» — моды → сабмоды по `config.json`: имя, автор, приоритет с учётом `user.json`, пометка «выкл».
  - Поиск по пути.
  - Можно открыть `.hkx` с диска или перетащить его в окно.
- **Таймлайн** в духе TAE:
  - строка на каждую категорию: Precision, PIE/FX, SDSCombat, SCAR, MCO/BFCO, события атаки, звук, шаги, root motion, прочее;
  - точки-ромбы и полосы для пар начало/конец: окна MCO/BFCO, `Collision_Add`→`Remove`/`Duration`, TargetLock, ReachTarget, CastOK;
  - линейка в кадрах или секундах, сетка кадров, плейхед;
  - root motion свёрнут в одну строку с кривой скорости, под ней — строка «значения root» с числами animmotion (x, y, z) и animrotation (↻°); при плотных ключах подписываются те, на которые хватает места, приближение показывает все. Галочка «значения root» в панели таймлайна прячет строку.
- **Таймлайн — мышь.**
  - Время (плейхед) меняется только на линейке «кадры/секунды»: клик или перетаскивание.
  - В строках аннотаций клик выделяет (по пустому месту — снимает выделение), а плейхед не двигается.
  - Аннотация или полоса захватывается по точке нажатия и сдвигается на ход мыши, без прыжка.
  - Перетаскивание пустого места прокручивает таймлайн.
  - **Наложенные ромбы** на одном кадре: каждый клик по стопке выбирает следующую аннотацию, подсказка показывает весь список (▶ — выбранная), ПКМ даёт меню «В этой точке» с выбором. Перетаскивание берёт выбранную из стопки.
- **Правка аннотаций.**
  - Перетаскивание по времени с привязкой к кадрам (отключается).
  - Двойной клик по строке — новая аннотация по шаблону этой строки.
  - ПКМ на таймлайне или в списке «Аннотации» — меню на плейхед:
    - «Добавить аннотацию» — шаблоны по группам (Precision, SDSCombat, MCO/BFCO, атака, SCAR, PIE). Составные шаблоны ставят сразу несколько аннотаций одним шагом отмены:
      - `Collision_Add.Node(WEAPON)` / `Node(SHIELD)` + `Collision_Remove.Node(WEAPON/SHIELD)` через 5 кадров;
      - `MCO_Windows` — `MCO_WinOpen` и `MCO_PowerWinOpen`, через 10 кадров `MCO_WinClose` и `MCO_PowerWinClose`;
      - `PIE.@SGVI|MCO_next(power)attack|1` — `MCO_nextattack|1` и `MCO_nextpowerattack|1`;
    - «Добавить свою аннотацию…» — окно по центру с полем ввода; «Добавить» (или Enter) ставит аннотацию на плейхед, Esc — отмена;
    - «Избранные аннотации…» — окно по центру со списком избранного: клик ставит аннотацию на плейхед, ✕ убирает из списка, поле и кнопка «Add Favorite» добавляют новую аннотацию в список (на таймлайн не ставят). Избранное хранится в настройках;
    - «Удалить выбранную».
  - Инспектор: время в секундах и кадрах, текст, разобранные поля. Для `SCAR_ActionData` и `SDS_NPC_*` поля редактируются числами.
  - Отмена/повтор, копирование и вставка на плейхед.
- **Рендер-окно 3D** (этап 1):
  - скелет расы из `meshes\actors\<папка клипа>\character assets\skeleton.hkx`;
  - тело `character` (malebody/hands/feet/head из сборки) со скиннингом по позе клипа;
  - декод spline- и interleaved-анимаций;
  - root motion по `animmotion`/`animrotation` (вкл/выкл), путь NPC и маркеры аннотаций на нём, линии скелета поверх;
  - камера: ЛКМ — вращать, ПКМ — сдвиг, колесо — зум, «Камера за NPC».
  - Режим «Сверху 2D» — прежний вид пути сверху.
  - У существ (не `character`) пока показывается только скелет; тела, броня и оружие NPC из ESP появятся на этапе 2.
- **NPC из ESP** (этап 2, вкладка «Персонаж»):
  - Поиск по EditorID, имени (русские имена из `.STRINGS`) или FormID среди 14 495 NPC сборки.
  - Индекс записей NPC_/RACE/ARMO/ARMA/OTFT/LVLI/LVLN/WEAP строится при загрузке сборки, примерно за 0,3 с. Побеждает последний плагин в порядке загрузки, удалённые записи учитываются.
  - Шаблоны: внешность берётся из TPLT, если стоит флаг «traits», инвентарь — если стоит флаг «inventory».
  - Раса задаёт скелет (ANAM, мужской или женский) и рост. Масштаб NPC = NAM6 × рост расы; root motion масштабируется вместе с ним.
  - Броня — из аутфита по умолчанию (DOFT → OTFT; у уровневых списков берётся первая запись). Для каждой брони выбирается ARMA своей расы или расы для брони, модель MOD2/MOD3 по полу. Если слоты уже заняты, вещь пропускается.
  - Скин NPC или расы виден, если надетая броня не занимает ни одного слота, заявленного самим ARMO скина (цельный скин с лишними слотами, например под маской, остаётся). Если ни один ARMA не подходит к расе, берётся ARMA для DefaultRace — как в игре (кастомные расы SDS, например Хевнорак).
  - Голова — FaceGen `facegeom/<плагин>/<id>.nif`. Если его нет, ставится общая голова расы; под шлемом без лица она скрыта, а волосы прячутся, если занят слот 31.
  - Оружие — из инвентаря (CNTO, уровневые списки раскрываются). В руку берётся первое оружие ближнего боя; оно висит на узле `WEAPON` (лук — на `SHIELD`) из skeleton.nif. Список оружия переключается.
  - Части брони можно включать и выключать. «Сбросить на тело по умолчанию» возвращает тело папки клипа.
  - Кости, которых нет в Havok (WEAPON, SHIELD, ножны, а также кости, существующие только в NIF брони — плащи, волосы), следуют за ближайшей анимированной костью жёстко, без физики.
  - Если клип рассчитан на другой скелет, рендер-окно об этом предупреждает.
  - Проверено на `SDS_GrandBoss_Vampire_Llandral` (DarkElfRaceVampire, доспех Daemon, катана) и `SDS_Bandit_BanditBossGhunzul` (орк, броня Elmlock, двуручный меч).
- **Хитбоксы Precision** (этап 3; переключатель и список — во вкладке «Сцена»):
  - Правила Precision 2.0.4:
    - `Collision_AttackStart` открывает атаку; `Add` и `Remove` до неё игнорируются.
    - `Add` требует `Node()`; имена событий и параметров читаются без учёта регистра.
    - `Remove.Node()` снимает первую коллизию на узле, сравнение с учётом регистра.
    - Особенность `Remove.ID()`: если после совпадающих коллизий в списке ничего нет, снимается только одна из них.
    - `AttackEnd` / `Cancel` / `attackStop` / `staggerStart` снимают всё и закрывают атаку.
    - `Duration(x)`; `Duration(0)` = fDefaultCollisionLifetime, у силовой атаки (в пути клипа есть «power») — с множителем.
    - Капсула отдачи (синяя) убирается на `HitFrame`.
  - **Редактор Precision в инспекторе** — для любой аннотации `Collision_*`:
    - выбор события: AttackStart / Add / Remove / ClearTargets / AttackEnd / Cancel;
    - все параметры со страницы мода с галочкой «есть / нет» и подсказкой:
      - `Node` — поле и список костей скелета; ● — у кости есть своя капсула или считается размер оружия;
      - `ID`;
      - флаги `NoRecoil`, `NoTrail`, `TrailUseTrueLength`, `WeaponTip`;
      - числа `DamageMult`, `Length`, `LengthMult`, `Radius`, `RadiusMult`, `Duration`, `Scale`, `TrailLifetimeMult`, `TrailBaseColorScaleMult`;
      - `Rotation` / `Translation` (x, y, z) и `GroundShake` (сила, длительность, частота);
      - `TrailBaseColorOverride` (палитра) и `TrailMeshOverride` (путь).
    - Текст собирается заново в порядке документации; разделитель (`.` или `|`) сохраняется, неизвестные параметры остаются в конце.
    - Перетаскивание числа — один шаг отмены.
    - Ниже формы показаны итоговая длина и радиус капсулы, время жизни коллизии и замечания.
    - Следы (trails) в рендере не рисуются, их параметры только редактируются.
  - Параметры можно разделять и `.`, и `|` (`Collision_Add.Node(NPC R Calf [RClf])|ID(1)|Scale(2)`). Флаги `NoRecoil` и `WeaponTip` распознаются.
  - Размеры:
    - `WEAPON`: длина = max(длина модели оружия в руке или `Length()`, fMinWeaponLength) × fWeaponLengthMult × LengthMult × Scale; радиус = fWeaponCapsuleRadius или `Radius()`. Капсула идёт по оси +Y узла WEAPON.
    - `SHIELD`: минимальная длина.
    - Другие кости: своя капсула из skeleton.nif (в скелете SDS их 18), длина × множители. Если у кости капсулы нет, размер приблизительный, и это помечено.
    - `Translation()` и `Rotation()` применяются к узлу. В режиме «как игрок» действуют множители игрока.
  - Настройки читаются из сборки: `MCM\Config\Precision\settings.ini`, поверх него `MCM\Settings\Precision.ini`. В SDS: радиус 14, длина ×1.1, минимум 85, отдача у NPC выключена.
  - В 3D: красная капсула атаки, синяя капсула отдачи и след конца капсулы от её начала до текущего кадра.
  - Строка Precision на таймлайне теперь строится по симуляции правил: полоса показывает реальную жизнь коллизии и причину её конца.
  - В инспекторе для аннотации `Collision_*` видны её коллизия и замечания (например, «игнорируется: до Collision_AttackStart»).
  - Проверено:
    - `bfco_attack3` Snow Elf King: капсула WEAPON идёт вдоль катаны и двуручника.
    - `H2H_PowerAttack1`: капсулы бедра, голени и стопы при ударе ногой.
  - Не моделируется: следы (trails) с цветами, `DamageMult` / `GroundShake`, per-weapon toml, скорость оружия, коллизии, которые Precision добавляет сам в клипах без `Collision_*`.
- **Путь NPC с SDSCombat** (этап 4; настройки — во вкладке «Сцена», раздел «Цель и SDSCombat»):
  - **Манекен-цель** (игрок): дистанция и угол от NPC в начале клипа; 0° — прямо перед ним, плюс — справа.
  - Клип проигрывается кадр за кадром (60 Гц) так, как это делает `SDSCombat.dll` (`TargetLock.cpp`):
    - **`TargetLockOn` / `TurnSpeed`**: NPC доворачивает на цель не быстрее, чем сила × fMaxEngineTurnSpeed. Сила 1 (или без числа) — предел движка, около 229°/с, либо `[TargetLock] fTurnSpeed`, если он задан. Сила 0 — никакого поворота.
    - **`TargetLockOff`**: поворот отдаётся ИИ. Его скорость задаётся вручную («Поворот ИИ без лока», по умолчанию 0): в игре она зависит от ИИ и расы.
    - **`StopRotation`**: курс фиксируется в момент аннотации (`bHoldHeading`).
    - **`TargetLockReset`**: состояние сбрасывается. Приоритет: Reset > Stop > Off > On.
    - **Направление шага** — из кривой `animmotion` относительно текущего курса (как `[AnimMotion]`), поэтому рывок идёт туда, куда NPC развернулся. Выпрямление под локом (`bStraightRootMotion`) действует только без animmotion — как в плагине.
    - **`BumpOff` / `BumpOn`** (и написание `SDS_NPCBumpOff` / `SDS_NPCBumpOn`): отключение «магнетизма» движения Animation Motion Fix до BumpOn или конца клипа — на таймлайне полосой «SDS_NPC_BumpOff», в шаблонах SDSCombat; на путь в студии не влияет.
    - **`ReachTarget.ref|min|max|arrive`**: дистанция D замеряется один раз в момент аннотации; шаги вперёд × k = clamp(D − arrive, min, max) / ref. ref, min и max умножаются на масштаб NPC, k ограничен `[ReachTarget] fMinScale/fMaxScale`. Действует до `ReachTargetEnd` или конца клипа.
  - Настройки берутся из `SKSE\Plugins\SDSCombat.ini` сборки. Если SDSCombat.dll в сборке нет или учёт выключен в «Сцене», аннотации `SDS_NPC_*` игнорируются.
  - **3D:**
    - путь с SDSCombat — цветом, без него — серым, для сравнения;
    - манекен цели и линия до него;
    - кольца `arrive` вокруг цели;
    - стрелка курса NPC: голубая — лок, красная — StopRotation, жёлтая — без лока.
    - Персонаж, хитбоксы Precision и их следы идут по этому же пути.
  - **В строке состояния:** позиция, курс, дистанция и угол до цели, режим лока с его °/с и множитель рывка.
  - **Во вкладке «Сцена»:** расчёт каждого ReachTarget (дистанция, сколько нужно пройти, k) и конечная точка с SDSCombat и без.
  - Вид «Сверху 2D» использует тот же путь и показывает цель.
  - Проверено на `bfco_attack3` Snow Elf King: цель на 400 под 40°, лок доворачивает на неё, ReachTarget даёт ×0.69 и ×0.31.
  - **Ограничения:** цель стоит на месте. Поворот ИИ без лока задаётся вручную. Задержка в кадр между скоростью поворота ИИ и самим поворотом и упор в предел движка моделируются приближённо.
- **OAR** (этап 5; вкладка «OAR» и библиотека в режиме OAR):
  - **Библиотека:**
    - моды → сабмоды из сборки с приоритетом и пометками «выкл» и «user.json»;
    - кнопка «Добавить папку OAR с диска…»: папка мода, папка `OpenAnimationReplacer` или целый мод — ищутся все `config.json`, с диска клипы открываются напрямую;
    - у каждого сабмода есть пункт «⚙ свойства и экспорт»: он выбирает сабмод и открывает вкладку OAR (даже если её закрыли в раскладке).
  - **Открытие клипа** из OAR-сабмода сразу выбирает этот сабмод во вкладке OAR.
  - **Вкладка OAR — сабмод:**
    - мод, автор, описание, число клипов;
    - откуда взят конфиг; если действует `user.json`, выводится предупреждение;
    - правка `name`, `description`, `priority`, `disabled`, `interruptible`, `replaceOnLoop`, `replaceOnEcho`;
    - условия деревом (НЕ, AND/OR/XOR с вложенностью) и редактор их JSON с проверкой;
    - предупреждение, если тот же приоритет у сабмода с общими клипами (победитель неоднозначен).
  - **Вкладка OAR — «Кто заменяет этот клип»:**
    - все сабмоды сборки и внешних папок, заменяющие ту же анимацию, по приоритету;
    - ★ — наивысший включённый; место открытого сабмода, например «59 из 451»;
    - базовый клип без OAR и мод, из которого он взят;
    - любую строку можно выбрать или открыть. Легаси-папки DAR не учитываются.
  - **Экспорт** в папку вывода (`meshes\actors\<проект>\animations\OpenAnimationReplacer\<мод>\<сабмод>`):
    - «Переопределить на месте (user.json)» — только конфиг рядом с оригиналом. Чужой мод не меняется: OAR берёт `user.json` вместо `config.json`.
    - «Новый сабмод» — копия рядом, имя папки + « SDS», приоритет +1, клипы копируются.
    - «Новый OAR-мод» — сабмод в отдельном OAR-моде «SDS Anim Studio» с собственным `config.json` мода.
    - Клипы берутся с правками студии: открытый клип с несохранёнными правками записывается через запись аннотаций; если правленая копия уже лежит в папке вывода, берётся она.
    - Конфиг сохраняет все прочие ключи оригинала (`replacementAnimDatas`, `overrideAnimationsFolder` и т. д.).
    - Если записан `config.json` на новом месте без клипов, лог предупреждает, что сабмод ничего не заменит.
  - Проверено:
    - библиотека сборки: 118 OAR-модов;
    - `bfco_attack1` Малении: 451 конкурент, лидер — Snow Elf King с приоритетом 1684911724;
    - тест сканирования папки с диска и экспорта с правленым клипом.
- **SCAR** (этап 6; вкладка «SCAR», меню «SCAR», зоны в 3D):
  - **Ключи `SCAR_ActionData`** — все, что читает SCAR 2.0 (по SCAR.dll): `IdleAnimation`, `Type`, `MinDistance`/`MaxDistance`, `StartAngle`/`EndAngle`, `Chance`, а также `WeaponLength`, `TriggerStartTime`/`TriggerEndTime`, `CoolDownTime`, `CoolDownAlias`, `VariantID`, `ConditionsAlias`. Неизвестные ключи сохраняются в исходном порядке.
  - **Типы:** RA/RPA (правая обычная и силовая), LA/LPA (левая), BA/BPA (щит), DA/DPA (двойная), IDLE. У каждого свой цвет.
  - **Круг сверху:**
    - NPC в центре смотрит вверх, + угол — вправо; кольца дистанций и лучи через 30°;
    - каждое ActionData — сектор кольца, сектор через спину (Start > End) поддерживается;
    - клик по зоне выбирает действие;
    - у выбранного тянутся белые точки (Min/MaxDistance, шаг 5) и жёлтые (Start/EndAngle, шаг 1°) — одно перетаскивание = один шаг отмены;
    - зелёная цель перетаскивается и двигает манекен-цель сцены (общий с SDSCombat).
  - **Проверка цели** на плейхеде, с учётом пути NPC и его курса: «✔ цель в зоне», «в зоне, вне окна времени» (TriggerStart/EndTime) или ✗. Активные зоны подсвечены.
  - **Список и редактор:** список ActionData клипа со временем; полный редактор (тип, IdleAnimation, числа, дополнительные ключи с галочками); добавление ActionData нужного типа и `SCAR_ComboStart` на плейхед, удаление.
  - **3D:** зоны лежат на земле вокруг NPC в его текущей позиции и курсе, активные ярче. Переключатели — в «Сцене» и в меню SCAR.
  - Проверено на `bfco_attack3` Snow Elf King: два ActionData (RA 0–450 и RPA 0–350, полный круг), цель на 245 единиц попадает в обе зоны.
  - **Не моделируется:** бросок Chance, кулдауны, ConditionsAlias, учёт длины оружия (WeaponLength показывается, но не прибавляется). Момент выбора действия — `SCAR_ComboStart` — показан только списком.
- **Граф комбо SCAR и симулятор** (вкладка «Граф комбо», меню SCAR):
  - **Набор (moveset)** — игровое состояние OAR-мода: условия одного из его сабмодов без проверки `SCAR_AttackVariants`. Условия OAR накладываются, поэтому в набор входят все сабмоды, чьи условия — подмножество условий состояния. Например, во «Nakrin Fase2Main» (ключевое слово + эффект фазы 2) работают и варианты V1–V4 с одним ключевым словом, и клипы fase1main, которых нет в fase2main (пересечения решает приоритет). По умолчанию берётся самый общий набор, где лежит открытый клип.
  - **Граф:**
    - узлы — клипы, рёбра — `SCAR_ActionData`;
    - строится от `scar_*` dummy (или от открытого клипа);
    - тип действия даёт клип: RA → `bfco_attack{N}`, RPA → `bfco_powerattack{M}`, где N и M выставил текущий клип через `PIE.@SGVI|MCO_nextattack|N` / `MCO_nextpowerattack|M` (без них — 1);
    - `VariantID` → `SCAR_AttackVariants` → OAR выбирает сабмод с наивысшим приоритетом среди подходящих: вариантный сабмод только для своего V, базовый — для любого;
    - рёбра раскрашены по типу и подписаны: дистанция, угол, шанс, вариант;
    - действия, которые не сводятся к клипу (IDLE, LA, BA…), и клипы, которых нет в наборе, показаны висящими стрелками с подписью;
    - клипы без ActionData помечены как «конец цепочки».
  - **Граф обновляется сам**, когда в открытом клипе меняются `SCAR_ActionData`, `SCAR_ComboStart` или `MCO_next…` (удалили переход — ребро пропало); раскладка, фокус и путь сохраняются.
  - **Мышь:**
    - клик по узлу открывает клип;
    - клик по ребру открывает исходный клип и выделяет это ActionData;
    - узлы перетаскиваются, пустое место двигает холст, колесо — масштаб, «Раскладка» расставляет узлы заново.
  - **«Только следующие атаки»** (+ «шагов: N»): показывает только выбранный клип (клик по узлу; без клика — открытый в студии) и клипы, в которые он ведёт за N переходов. Узлы раскладываются компактно: столбец на шаг, порядок — как SCAR перебирает действия. Остальная «вермишель» скрыта.
    - **Путь:** клик по следующей атаке переносит фокус на неё, а пройденные клипы остаются слева в ряд, рёбра между ними подсвечены. Над графом — строка «Путь: dummy → attack1 → attack2», клик по любому звену возвращает к нему; «⟲ сбросить путь». Симулятор в этом режиме ведёт путь сам; при конце цепочки путь остаётся на экране, новая цепочка начинает новый путь.
  - **Фильтр «Цель»:** дистанция и угол (или «из сцены») → на рёбрах вероятность перехода, недоступные гаснут.
  - **Выбор SCAR:** время аннотации ActionData — её вес/приоритет. Действия перебираются от самого позднего времени: у кого время больше, тот проверяется первым; если цель в его зоне, он бросает Chance; первое удачное побеждает. Низкий шанс не снимает приоритет, а только даёт его пропустить.
  - **Симулятор:**
    - «Старт» — с dummy или с открытого клипа; «Шаг» — одно решение SCAR;
    - режим «цель по пути NPC»: клип открывается в студии, дистанция и угол до цели считаются на каждом `SCAR_ComboStart` с root motion и SDSCombat, после перехода цель переносится в следующий клип;
    - иначе цель неподвижна относительно NPC, и доступна кнопка «×20» — 20 шагов сразу;
    - шанс бросается или переход выбирается вручную из списка с вероятностями;
    - если ничего не выпало или цель вне зон, клип доигрывается и цепочка возвращается в dummy;
    - лог цепочки (время, цель, тип, шанс, вариант, следующий клип) и частота клипов; пройденное ребро и текущий узел подсвечены.
  - Проверка без GUI: `--tab combo --combo-sim <шагов> [--combo-next] --target-dist .. --target-angle ..`.
  - **Не моделируется:** кулдауны, ConditionsAlias, TriggerStart/EndTime, ситуативные сабмоды с другими условиями (например, переход фазы по здоровью) — это отдельный набор.
- **Проекты** (меню «Файл»):
  - «Сохранить проект / как…», «Открыть проект…», «Недавние проекты»; файлы `.sdsproj` (JSON), по умолчанию в `dist\Projects`.
  - **В проекте сохраняются:**
    - клип (путь в сборке или на диске) и весь список аннотаций, включая несохранённые правки — после открытия они видны как правка, отменяемая одним Ctrl+Z;
    - плейхед, скорость, выделение;
    - NPC (`Плагин|0xID`), оружие, скрытые части;
    - все настройки сцены (цель, SDSCombat, Precision, трейлы, FX, SCAR, слои, строки таймлайна), камера, масштаб и сдвиг таймлайна;
    - внешние OAR-папки и выбранный сабмод.
  - Если сборка ещё грузится, проект откроется после загрузки. Если проект сделан на другой сборке или профиле, в лог выводится предупреждение.
  - При закрытии студия сама сохраняет сессию (`last_session.sdsproj`): «Файл → Восстановить последнюю сессию».
- **PIE / FX** (этап 7):
  - `PIE.$Alias` разбирается по всем `SKSE\PayloadInterpreter\Config\*.ini` сборки; `PIE.@…` берётся как есть.
  - **`@CAST` / `@CASTRIGHT` / `@CASTLEFT`** → заклинание (SPEL/ENCH) → его эффекты (MGEF) → арт:
    - арт каста (MGEF DATA @92) на `NPC R/L MagicNode`;
    - арт эффекта (@96) на актёре, если каст на себя (6-й параметр = 1), иначе на цели;
    - арт зачарования (@116) на `WEAPON`.
    - Длительность берётся из EFIT.
  - **`@APPLYSPELL`** держит арт до `@UNAPPLYSPELL` того же заклинания или до конца клипа. **`@PLAYPARTICLE|nif|часть тела|масштаб|время|флаги|x|y|z`** ставит NIF на часть тела (33+ — оружие → `WEAPON`, 9/38 — щит, 3 — голова…). Остальные команды (`@SGVI`, `@CAMSHAKE`, `@SETGHOST`…) помечаются «без визуала».
  - Алиас может состоять из нескольких строк-команд; префикс `![сек]` — задержка, она сдвигает начало арта.
  - **Инспектор PIE** — параметры по README PayloadInterpreter:
    - прямая `PIE.@КОМАНДА|…` редактируется формой: у каждого параметра своё имя и тип (эффективность, магнитуда, «на себя», требования и стоимость HP/выносливости/магии, часть тела, масштаб…), галочки для bool, задержка сохраняется;
    - у алиаса показан каждый шаг с задержкой и подписанными параметрами;
    - дальше цепочка: заклинание → арт каждого эффекта (модель, привязка, время начала и конца) → замечания.
  - **Рендер арт-NIF:**
    - `AttachT` (`NamedNode&WEAPON` и т. п.) — корень арта вешается на этот узел, как BSAttachTechniques в игре;
    - эмиттеры по мешу цели (клинковые эффекты: Отар, `SDS_SNEK_BladeEnchantFX`) — арт ставится на `WEAPON` и излучает с геометрии оружия в руке;
    - последовательности BeginLoopEnd: mBegin один раз, затем mLoop по кругу; треки рождения, активности и скорости эмиттеров, видимость узлов;
    - анимация мешей эффектов: цвет, альфа, эмиссия и UV из последовательности и свободных контроллеров, трансформы узлов, билборды (`NiBillboardNode`) развёрнуты к камере;
    - меши эффектов: текстура, палитра greyscale-to-palette (цвет и альфа), цвет вершин и tint, альфа или аддитив; меши рефракции (карта нормалей) не рисуются — в игре они только искажают фон;
    - системы частиц — через симулятор Aether (сверен с SkyrimSE 1.5.97): эмиттеры, силы, цвет и размер по жизни, вращение, атласы, палитры; strip-системы — лентами. Назад по времени симуляция переигрывается с начала.
  - **Не моделируется:** шейдеры эффектов на теле (EFSH), снаряды, mEnd (конец эффекта при снятии). Звуки эффектов — см. «Звук».
  - Отладка: переменная окружения `SDS_FX_DEBUG=1` печатает меши, системы и клипы каждого арт-NIF.
  - Проверено на Короле снежных эльфов (`SDS_GrandBoss_SnowElf_SnowElfKing`, `bfco_attack4`: `$SDSSNEKBladeVFX`, `$SDSSNEKFrostExplosion`) и Отаре (`SDS_GrandBoss_DragonPriest_Otar`, `bfco_powerattack4`: огненный клинок, MagicRelease01).
- **Звук** (🔊 и громкость — в панели таймлайна, сохраняются в настройках):
  - при проигрывании звучит каждое событие, через которое проходит плейхед:
    - `SoundPlay.<EDID>` — SNDR или SOUN (→ его SNDR) по EditorID;
    - звуки эффектов PIE: у `@CAST` звук «выпуск» MGEF, а при касте на себя ещё и «попадание»;
    - `weaponSwing` / `weaponLeftSwing` — звук взмаха оружия NPC (WEAP TNAM), без оружия — `WPNSwingUnarmed`;
    - `Foot*` (FootLeft, FootScuffRight…) — набор шагов обуви NPC (ARMA ступней → FSTS; без NPC — FSTBarefootFootstepSet) → Footstep с этим тегом → набор ударов → удар по выбранной поверхности (или её родительскому материалу) → звук. Поверхность выбирается во вкладке «Сцена» → «Звук» (по умолчанию MaterialStone).
  - Инспектор события взмаха или шага показывает цепочку записей и кнопку «▶ Прослушать».
  - Как в игре: случайный файл из ANAM, статическое ослабление и разброс дБ (BNAM), сдвиг и разброс высоты, громкость категории SNCT по цепочке родителей, цикличные звуки. Если `.wav` нет, берётся `.xwm`, затем `.fuz`.
  - Вывод — XAudio2 2.9 из Windows: PCM и ADPCM `.wav`, xWMA `.xwm` и `.fuz` без сторонних декодеров. Скорость таймлайна меняет и высоту звука.
  - Пауза глушит звук. Перемотка и прыжки плейхеда молчат. В конце клипа без цикла хвосты доигрывают.
  - Инспектор `SoundPlay` показывает SNDR, категорию, ослабление, разброс высоты и файлы, кнопка «▶ Прослушать». В инспекторе PIE — строки 🔊 со звуками эффектов.
  - Не найденный дескриптор или файл пишется в лог один раз.
  - Проверка без GUI: `sds-anim-studio.exe --sound-test <пути в сборке>…` — разбирает файлы и проверяет, что XAudio2 их принимает. Ничего не звучит.
- **Трейлы Precision** (переключатель и сводка — во вкладке «Сцена»):
  - Лента по траектории клинка WEAPON/SHIELD от начала коллизии; живёт fTrailSegmentLifetime и гаснет за fTrailFadeOutTime, сегментов в секунду — uTrailSegmentsPerSecond (из MCM-ini сборки).
  - Длина — по мешу оружия; по длине коллизии, если стоит `TrailUseTrueLength` или bTrailUseAttackCollisionLength.
  - **Откуда берётся вид трейла**, по убыванию важности:
    - параметры аннотации `TrailBaseColorOverride`, `TrailBaseColorScaleMult`, `TrailLifetimeMult`, `TrailMeshOverride` (`NoTrail` отключает трейл);
    - `[[TrailDefinition]]` из `SKSE\Plugins\Precision\*.toml` сборки (17 определений в SDS), подобранный по оружию NPC — WeaponNames, WeaponKeywords, EnchantmentNames, EffectNames, EffectKeywords, EffectShaders, с `All` и `Priority`, как в Precision;
    - цвет по умолчанию из MCM.
  - Текстура ленты берётся из NIF трейла (`attacktrail.nif` или override).
  - Сводка показывает, какое определение досталось текущему оружию.
- **Сцена.** Вкл/выкл root motion, пути, сетки и строк таймлайна. Аннотации SDSCombat учитываются, только если в сборке есть `SKSE\Plugins\SDSCombat.dll`.
- **Сохранение HKX** (Ctrl+S): копия клипа с новыми аннотациями пишется в папку вывода с тем же путём от Data. Исходный мод не трогается. Перед записью файл перечитывается и сверяется: все классы и данные анимации должны совпасть, а аннотации — быть ровно заданными. Если сверка не прошла, файл не пишется.
  - **Папка вывода поверх сборки:** если в папке вывода уже лежит сохранённая копия клипа, студия открывает её (источник «папка вывода (поверх <мод>)»), даже когда папка вывода не подключена в MO2. Сохранённые правки видны при повторном открытии.
  - **Черновики:** при переходе на другой клип несохранённые правки откладываются и возвращаются, когда клип открывают снова (до закрытия студии). Возвращённые правки — один шаг Ctrl+Z.
  - Ctrl+S и смена клипа ждут два кадра: поле, которое ещё в фокусе (текст аннотации, число вроде `arrive`), успевает применить ввод.
  - Проверено на 464 клипах из `hkanno64`: ошибок нет, 177 файлов совпали байт-в-байт. В остальных аннотации записаны в порядке по времени, а не в исходном порядке; для игры это неважно.
- **Экспорт** `anno.txt` в формате hkanno64 — меню «Файл».

## Сборка из исходников

```
git clone <адрес репозитория>
cd <папка репозитория>
cargo build --release -p sds-anim-studio
cargo test
```

Rust stable (проверено на x86_64-pc-windows-gnu; msvc тоже подходит). Всё нужное лежит в репозитории: крейты Aether (`vendor/aether`: nif, core, codecs; GPL-3.0) и serde-hkx от SARDONYX (`vendor/serde-hkx`, MIT/Apache-2.0), без их тестовых данных. Готовый exe — `target\release\sds-anim-studio.exe`. При первом запуске укажите во вкладке «Библиотека» папку MO2 и профиль (или папку Data), а рядом с exe появятся `sds_anim_studio.json` и папка `Output`.

Проверка интерфейса без ручного запуска:
`sds-anim-studio.exe --screenshot out.png --open "<путь в Data>" --time 0.75 --select 3 [--oar] [--dist 200] [--yaw 25] [--skeleton] [--save]`. `--npc <EditorID>` одевает персонажа, `--tab npc|scene|anno|inspector|oar|scar|combo`, `--project <файл>` открывает проект, `--save-project <файл>` сохраняет состояние перед снимком открывает вкладку; `--open` принимает и путь на диске, `--select-text <подстрока>` выделяет аннотацию, `--target-dist` и `--target-angle` ставят цель. `--save` добавляет тестовую аннотацию и сохраняет HKX, чтобы проверить запись от начала до конца.

Проверочные примеры:
- `cargo run -p sds-hkx --example verify_kf -- skeleton.hkx anim.hkx anim.kf` — сверка декодера с KF-экспортом. На `D:\Blender3.1\Distar\test3.0` 83 кости из 84 совпали точно, одна кость в KF отличается.
- `cargo run -p sds-hkx --example roundtrip -- *.hkx` — перезапись аннотаций со сверкой.
- `cargo run -p sds-records --example npcs -- "<MO2>" "<профиль>" фильтр` — найти NPC и показать, что на нём будет надето.
- `cargo run -p sds-vfs --example find -- "<MO2>" "<профиль>" подстрока…` — поиск файла в сборке и мода-источника.

## Структура

| Крейт | Назначение |
|---|---|
| `crates/vfs` | MO2 → виртуальная Data (loose + BSA через Aether) |
| `crates/hkx` | HKX (packfile 2010.2): сведения о клипе и аннотации (`lib.rs`), скелет и декод spline/interleaved, позы (`anim.rs`), запись аннотаций со сверкой (`write.rs`) |
| `crates/records` | индекс записей порядка загрузки (`lib.rs`), сборка внешности NPC (`npc.rs`), арт заклинаний и сведения об оружии (`fx.rs`) |
| `crates/i18n` | язык интерфейса: `t!("рус", "eng")`, `tf!` для форматирования, `tr!` для константных таблиц |
| `crates/anno` | разбор аннотаций по типам, пары начало/конец, правила Precision (`precision.rs`), путь SDSCombat (`sdscombat.rs`) |
| `crates/app` | egui + egui_dock: библиотека, рендер (`render.rs` wgpu, `viewport3d.rs`, `character.rs` скиннинг и кости, `npc_panel.rs` вкладка «Персонаж», `precision_view.rs` капсулы Precision, `sds_path.rs` путь с SDSCombat, `oar.rs` / `oar_panel.rs` OAR, `scar_panel.rs` SCAR, `pie.rs` / `fx.rs` FX и трейлы, `project.rs` проекты), таймлайн, инспектор, список аннотаций, сцена, лог |
